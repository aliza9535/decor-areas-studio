Security & Data Handling

Decor Areas Studio uses Pinterest OAuth, server-side secrets and explicit user approval for Pinterest write actions.

Workspace authentication

Workspace passwords are salted and hashed using a memory-hard password derivation function. Application sessions use random tokens stored in Secure, HttpOnly, SameSite cookies.

Pinterest OAuth

OAuth requests use a random state value. Pinterest application credentials remain server-side. OAuth access and refresh credentials are encrypted before storage and are not shown in the page interface.

Write protection

Mutating endpoints reject cross-site requests. Publishing, Board creation, scheduling and destructive actions require a specific user-selected item and explicit confirmation.

Scheduling

Approved scheduler records are stored in PostgreSQL. The server enforces a minimum 30-minute gap between active queued Pins. Scheduled execution uses only the authorization associated with the signed-in workspace.

Website import safety

The importer accepts public HTTP/HTTPS URLs, limits redirects and response size, and rejects local/private-network addresses. The public WordPress flow does not require admin credentials.

AI separation

AI generation is based on user-supplied text, article content and prompts. Pinterest API-derived account information is not intentionally supplied to the AI generation endpoint. User-uploaded JPEG/PNG privacy cleaning removes selected private metadata without recompressing image pixels; the product does not intentionally strip provenance or Content Credentials from AI-generated content.

Transport

The service uses HTTPS and security headers restricting framing, MIME sniffing, referrer leakage and unnecessary browser capabilities. Secrets are not committed to the public repository.
