Security & Data Handling

Decor Areas Studio is designed around Pinterest's OAuth Authorization Code flow, least-privilege scopes and explicit user approval for Pinterest write actions.

Authentication

OAuth requests use a random state value to protect the authorization flow. Pinterest passwords and Pinterest session cookies are never requested. Application credentials remain server-side.

OAuth credentials and refresh

Access and refresh credentials are encrypted before being stored in Secure, HttpOnly, SameSite first-party cookies. They are not available to page JavaScript. The server can use Pinterest's refresh-token flow to maintain an authorized connection without exposing tokens to the browser interface.

Write protection

Write actions are accepted only through same-origin POST requests. Creating a Pin, deleting a Pin or creating a Board is initiated for a specific user-selected item and requires explicit confirmation in the interface.

Data minimization

The current build does not persist Pinterest API-derived account, Board, Pin or analytics data in a server database. API information is requested on demand for the authorized user. Draft and planner metadata is browser-local and excludes OAuth secrets and persistent Pinterest analytics copies.

Transport and browser security

The application uses HTTPS. Security headers restrict framing, mixed content and unnecessary browser capabilities. Pinterest API credentials are never committed to the public code repository.

Policy safeguards

The product does not scrape Pinterest, provide unauthorized competitor research or benchmarking, automate hidden engagement actions, combine unrelated account data, or use Pinterest API-derived data to train or improve AI models.
