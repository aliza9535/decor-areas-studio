Security & Data Handling

Decor Areas Studio uses Pinterest's OAuth Authorization Code flow, least-privilege API access and explicit user approval for publishing actions.

Authentication

Workspace passwords are salted and hashed using a memory-hard password derivation function before storage. Application sessions use random server-generated tokens stored in Secure, HttpOnly, SameSite cookies. Pinterest OAuth requests use a random state value to protect the authorization flow.

Pinterest OAuth credentials

Pinterest application credentials remain server-side. Browser OAuth credentials are encrypted before being placed in Secure, HttpOnly cookies. For signed-in users who enable durable scheduling, Pinterest access and refresh credentials are also encrypted before database storage so the background worker can execute previously approved scheduled Pins and refresh expiring access tokens.

Write protection and user approval

Mutating application endpoints reject cross-site requests. Immediate publishing requires a confirmation prompt. Scheduler creation requires an explicit approval flag for the exact Pin, and the server enforces a minimum 30-minute gap between queued Pins.

Background publishing

The scheduler worker processes only records that contain an approval timestamp and are due for publication. The worker endpoint is protected by a secret and records success or failure status for each attempted Pin.

Website import safety

The article importer accepts only public HTTP/HTTPS URLs, limits redirects and response size, and rejects local and private-network addresses to reduce server-side request forgery risk.

Transport and browser security

The application uses HTTPS and security headers that restrict framing, MIME sniffing, referrer leakage and unnecessary browser capabilities. Secrets and OAuth credentials are not committed to the public code repository.
