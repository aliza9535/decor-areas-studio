Security & Data Handling

Decor Areas Studio is designed around Pinterest's OAuth Authorization Code flow and least-privilege access for the features currently demonstrated.

Authentication

OAuth requests use a random state value to protect the authorization flow. Pinterest passwords and Pinterest session cookies are never requested. Application credentials remain server-side.

OAuth credentials

Access and refresh credentials are handled as sensitive data in Secure, HttpOnly, SameSite first-party cookies. They are not available to page JavaScript and are not shown in the application interface.

Write protection

Write actions are accepted only through same-origin POST requests and require the user's explicit confirmation. Trial write testing is isolated to Pinterest Sandbox.

Data minimization

The current build does not persist Pinterest API-derived account, Board, Pin or analytics data in an application database. API information is requested on demand for the authorized user.

Transport and browser security

The application uses HTTPS. Security headers restrict framing, mixed content and unnecessary browser capabilities. Pinterest API credentials are never committed to the public code repository.

Environment separation

Pinterest Sandbox is used for Trial write testing. Production publishing is used only when the application has appropriate Pinterest access and the user has authorized the requested scopes.
